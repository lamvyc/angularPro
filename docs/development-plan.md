# MedFlow 开发计划

| 项 | 值 |
| --- | --- |
| 版本 | v1.0（第一阶段产出） |
| 方法 | 分阶段交付，每阶段可启动、可构建、可测试、可演示 |
| 总周期 | 约 7 周（单人全职估算，含缓冲） |
| 当前状态 | **P0 基础工程**（本阶段），M1–M6 待逐阶段实施 |

## 1. 交付策略

```text
P0 基础工程 ──► M1 权限体系 ──► M2 预约挂号 ──► M3 医生工作站
                                      │                │
                                      └──────► M4 电子病历 ──► M5 处方 ──► M6 药房
```

- 严格串行：每个模块依赖前序模块的领域对象与权限骨架。
- 每个模块结束必须满足 **DoD**（见第 5 节），并留下可复现的演示脚本。
- 每完成一个模块打一个 git tag（`phase-0`、`m1-iam` …），便于回看与讲解。
- 不提前实现后续模块的 UI；只保留接口与表结构的演进空间。

## 3. 模块计划

> 工期为单人估算，含编码、测试、自查与文档；不含需求反复。

### M1 权限体系（约 5 天）

| 类别 | 内容 |
| --- | --- |
| 数据库 | V2：科室、用户、角色、权限、关联表；内置 5 角色、7 用户、权限种子 |
| 后端 | 登录/刷新/登出/me；JWT 与 Redis 会话；登录锁定；用户/角色/科室 CRUD；角色授权；菜单树；数据范围解析；审计；权限注解 |
| 前端 | 登录页、AuthStore、Token 存储、鉴权/权限守卫、401 刷新队列、菜单渲染、权限指令、用户/角色/科室管理页、审计列表 |
| 测试 | 认证集成测试；5 角色 × 关键接口的权限矩阵测试；跨科室访问 403/404；刷新令牌重放；锁定与解锁；菜单过滤；ArchUnit |
| 验收 | 5 个账号登录看到不同菜单；无权限接口 403；授权变更 10 分钟内生效（缓存失效后立即）；审计可查 |
| 演示 | 管理员创建用户 → 分配角色 → 医生登录 → 直接访问管理接口被拒 |

**风险**：JWT 刷新并发、权限缓存一致性。**缓解**：单例刷新、版本号失效缓存、集成测试覆盖。

### M2 预约挂号（约 7 天）

| 类别 | 内容 |
| --- | --- |
| 数据库 | V3：患者、排班、号源、预约、收费单、退款单 |
| 后端 | 患者建档/查询；排班发布与号源生成；号源查询；预约（原子扣减 + 幂等 + 唯一约束）；取消/退号；签到创建就诊；收费/退款；日终过号任务 |
| 前端 | 患者选择/快速建档；号源日历；预约确认；预约列表与退号；签到；收费/退款 |
| 测试 | **50 线程抢 1 号源仅 1 成功**；重复幂等键回放；同患者重复预约拦截；取消后号源释放；退款失败重试；数据范围 |
| 验收 | 预约主链路可走通；并发测试通过；账单与退款状态正确；无超卖 |
| 演示 | 两个窗口同时抢最后一个号 → 一个成功一个提示已满 → 取消后号源回到可约 |

**风险**：并发测试偶发、跨日时区。**缓解**：固定时钟 `Clock` 注入、容器时区固定、断言业务结果。

### M3 医生工作站（约 6 天）

| 类别 | 内容 |
| --- | --- |
| 数据库 | V4：就诊、诊断、就诊事件 |
| 后端 | 候诊列表；接诊/结束/取消；诊断维护；病历草稿自动保存（Redis + DB）；乐观锁冲突；结束守卫 |
| 前端 | 候诊队列（自动刷新/轮询）、接诊页布局、诊断录入、自动保存状态条、冲突合并对话框 |

| 验收 | 医生可完整接诊并结束；冲突不丢数据；草稿可恢复 |
| 演示 | 两个浏览器同一病历编辑 → 后保存者看到冲突并合并 |

**风险**：自动保存频率、冲突合并体验。**缓解**：2 秒防抖 + 只在内容变化时保存 + 显式冲突状态。

## 5. 完成定义（DoD）

每个模块必须同时满足：

- [ ] 领域规则有单元测试，关键业务闭环有集成测试（真实 MySQL/Redis）
- [ ] 所有状态迁移有"非法路径"测试；错误码与文档一致
- [ ] 写接口具备权限校验、数据范围校验、幂等或唯一约束
- [ ] 审计事件写入且可查询
- [ ] Flyway 迁移可从空库重建；种子数据可重复执行
- [ ] 前端有加载/空/错误/无权限四态；移动端不作为目标但不得布局崩坏
- [ ] OpenAPI 注解完整，Swagger 可调试
- [ ] `./mvnw verify`、`pnpm lint`、`pnpm test`、`pnpm build` 全绿
- [ ] README/演示脚本更新；文档与实现无矛盾
- [ ] 代码评审清单通过（见第 7 节）

## 6. 测试策略

### 6.1 测试金字塔

| 层级 | 后端 | 前端 | 目标占比 |
| --- | --- | --- | --- |
| 单元 | JUnit 5 + AssertJ + Mockito（领域/状态机/校验器） | Vitest（Store、Pipe、校验函数） | 60% |
| 切片 | `@WebMvcTest`（安全/序列化/错误映射） | TestBed 组件测试 | 25% |
| 集成 | `@SpringBootTest` + Testcontainers（MySQL/Redis） | 不适用 | 10% |
| E2E | Playwright（M2 起，主链路） | 同左 | 5% |

### 6.2 必测清单（跨模块）

1. 状态机全迁移矩阵：合法迁移成功、非法迁移 409 且状态不变。
2. 并发：预约抢号、库存扣减、重复发药、重复提交。
3. 幂等：同键同体重放、同键异体冲突、事务回滚后重试。
4. 权限：角色 × 接口矩阵、跨科室、资源归属、未登录。
5. 数据完整性：审计与业务同事务、库存对账、病历哈希。
6. 边界：空明细、负数、超最大长度、过期、跨日、时钟边界。
7. 前端：四态渲染、冲突提示、刷新令牌队列、权限指令。

### 6.3 覆盖率门槛

| 范围 | 行覆盖 | 分支覆盖 |
| --- | --- | --- |
| `domain` 包 | ≥ 85% | ≥ 75% |
| `application` 包 | ≥ 75% | — |
| 前端 `state/` + `shared/utils` | ≥ 80% | — |
| 全局 | ≥ 70% | — |

### 6.4 测试数据

- 集成测试使用 Testcontainers 启动真实 MySQL 8.4 + Redis 8，每次测试类独立 schema 或事务回滚。
- 固定 `Clock`（`2026-10-26T09:00+08:00`）避免时间漂移。
- 不使用生产数据；姓名/手机号/证件号均为合成。

## 8. 风险登记

| # | 风险 | 概率 | 影响 | 缓解 | 触发信号 |
| --- | --- | --- | --- | --- | --- |
| R1 | Boot 4 / Jackson 3 生态问题 | 中 | 高 | 已验证核心链路；锁定版本；升级需回归 | 第三方库报 `NoClassDefFound` |
| R2 | Signal Forms 动态能力不足 | 中 | 中 | 静态表单使用；动态表单回退 Reactive Forms | 字段无法按 Schema 渲染 |
| R3 | 并发测试不稳定 | 中 | 中 | 固定线程数、断言结果、容器复用 | CI 偶发红 |
| R4 | 动态病历表单膨胀 | 中 | 高 | 字段白名单、规则 DSL 最小化 | Schema 出现任意脚本/表达式 |
| R5 | 工期估算偏乐观 | 高 | 中 | 每模块留 1 天缓冲；先可用再优化 | 连续两个里程碑延期 |
| R6 | 权限遗漏 | 中 | 高 | 权限矩阵测试、ArchUnit、代码评审 | 出现无注解写接口 |
| R7 | 演示数据被误当真实数据 | 低 | 高 | 页面标注、文档声明、禁止导入 | 出现真实姓名/证件 |

## 9. 交付后的学习与复盘

每个模块结束时写一段 `docs/retrospectives/mN.md`（后续阶段）：

1. 这个模块最容易出错的地方是什么？为什么？
2. 哪个并发场景最难测？测试如何证明正确？
3. 哪个设计后来被推翻了？触发原因是什么？
4. 如果重做，会删掉什么？

### 面试讲解锚点（预留）

| 主题 | 可讲的真实细节 |
| --- | --- |
| 防超卖 | 为什么不用"查余量再更新"；MySQL 条件更新 + 唯一索引 + 幂等表三层防线 |
| 乐观锁 | 版本冲突如何返回最新数据；自动保存如何避免互相覆盖 |
| 幂等 | 同键同体/同键异体/事务回滚三种情况的不同处理 |
| 状态机 | 领域层迁移表、非法迁移 409、审计与状态同事务 |
| 库存 | FEFO 分配、整单回滚、reserved_qty 与 stock_qty 的关系、对账 SQL |
| 权限 | RBAC + 数据范围、前后端双重校验、缓存失效 |
| 前端架构 | Signals vs RxJS 的边界、Signal Forms 与动态表单的分工 |
