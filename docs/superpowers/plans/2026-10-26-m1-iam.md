# M1 权限体系 Implementation Plan

> **For agentic workers:** 本计划按 TDD 顺序执行。测试先行（HTTP 契约测试 / Store 单测），观察失败后再实现。步骤使用 `- [ ]` 跟踪。

**Goal:** 完成登录、JWT 会话、RBAC（菜单/按钮/接口权限）、科室数据隔离与审计查询，使五类角色拥有真实可用的工作台与后台管理能力。

**Architecture:** 后端在 `auth` 模块实现认证与会话，`iam` 模块实现用户/角色/权限/科室/审计；所有写操作经 Application Service，审计与业务同事务；JWT 无状态访问令牌 + Redis 刷新令牌轮换 + 权限缓存。前端以 `AuthStore` 为核心，HTTP 拦截器负责 Bearer 与 401 单飞刷新，路由守卫与 `*appHasPermission` 指令消费同一权限集合；菜单完全由后端返回。

**Tech Stack:** Spring Boot 4.1.2 / Security 7.1.2 / MyBatis-Plus 3.5.18 / Redis 8 / Flyway 12；Angular 22.2.3 / Signals / Material 22 / Signal Forms / Vitest 5。

**Spec:** `docs/requirements.md`（M1 部分）、`docs/business-flows.md`（1.x、8）、`docs/database-design.md`（4.2、5、6）

## Global Constraints

- 所有时间 `Asia/Shanghai`；密码 BCrypt(12)；访问令牌 15 分钟，刷新令牌 7 天。
- 所有 `/api/v1/**`（除登录/刷新/ping/健康/OpenAPI）必须认证；写接口必须有权限注解。
- 错误响应统一 RFC 9457 Problem Details，扩展 `code`、`requestId`、`fieldErrors`。
- 审计只追加；禁止记录密码、令牌与病历正文。
- 数据范围：`ALL > DEPT > SELF`；不可见资源返回 404，越权动作返回 403。
- 前端权限只影响展示；后端必须重新校验。
- 演示账号密码统一 `Medflow@2026`，全部为合成数据。

## Review Focus

1. 刷新令牌重放与轮换：旧令牌二次使用必须失败并使会话失效。
2. 登录锁定：5 次失败后即使密码正确也应返回 423，且解锁后计数清零。
3. 权限缓存失效：角色授权/用户角色变更后，下一次请求立即生效。
4. 数据范围越权：医生携带其他科室 id 查询医生列表时不得返回数据，也不得通过前端隐藏绕过。
5. 审计完整性：失败登录、越权尝试是否被记录，且不含敏感字段。

## 验收标准

1. 五个账号登录后菜单不同；直接访问无权限路由 → 403。
2. 医生调用管理员接口 → 403；管理员无临床接口权限。
3. 医生只能看到本科室医生；跨科室查询无数据。
4. 5 次错误密码后 423，15 分钟后或管理员解锁恢复。
5. 刷新令牌轮换；旧令牌重放失败；登出后访问令牌立即 401。
6. 管理员授权后，目标用户下一次请求立即获得新权限。
7. 审计可查询登录失败、越权、用户/角色变更、科室变更。
